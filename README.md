## 📌 커밋 메시지 규칙 (Commit Convention)

우리 팀은 협업 시 아래의 규칙에 따라 커밋 메시지를 작성합니다.
**형식:** `[태그] 설명` (예: `[Feat] ls 명령어 옵션 구현`)

| 태그 (Tag) | 설명 (Description) | 사용 예시 |
| :--- | :--- | :--- |
| **`[Feat]`** | 새로운 기능 추가 | `[Feat] ls 명령어 구현`, `[Feat] 파이프 기능 추가` |
| **`[Fix]`** | 버그 수정 | `[Fix] 무한 루프 오류 해결`, `[Fix] 세그멘테이션 폴트 수정` |
| **`[Refactor]`** | 기능 변경 없는 코드 구조 개선 | `[Refactor] main 함수 로직 분리`, `[Refactor] 변수명 변경` |
| **`[Docs]`** | 문서(주석, README) 수정 | `[Docs] README에 커밋 규칙 추가`, `[Docs] 함수 주석 보강` |
| **`[Chore]`** | 빌드 설정, 패키지 매니저 설정 등 | `[Chore] Makefile 수정`, `[Chore] .gitignore 업데이트` |
